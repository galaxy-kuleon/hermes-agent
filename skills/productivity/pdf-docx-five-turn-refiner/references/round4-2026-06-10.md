## Implemented

### 1. Whitelisted q7 suggestion adapters

q7 `fix_suggestions` are now reified into deterministic patch adapters. The adapters are intentionally narrow and auditable.

Supported adapters:

```text
normalize_indentation
change_font
delete_paragraphs
```

Adapter behavior:

- `normalize_indentation`: parses q7 targets like `p[4]` / `p[4] and p[5]`, then clamps those paragraph indents to a sane range (`left_indent = 0.25in`, no hanging indent).
- `change_font`: parses q7 paragraph targets and applies a safe font inferred from `ooxml_hint`/rationale, e.g. `Courier New` for monospaced blocks.
- `delete_paragraphs`: source-gated duplicate deletion. Even if q7 asks to delete paragraphs, the adapter skips unless candidate/source evidence permits deletion. High-risk deletions also require `--allow-high-risk-delete`.

### 3. In-loop q7 suggestion application

`convert` and `refine` now support:

```bash
--apply-q7-suggestions
--allow-high-risk-delete
```

Example:

```bash
uv run .../pdfdocx5.py refine \
  source.pdf input.docx -o refined.docx \
  --judge-q7 --q7-xml-context --apply-q7-suggestions --turns 5
```

This lets XC run:

```text
candidate → normalize → QA/q7 → deterministic q7 patch → next turn → render QA
```

### 4. Clean CLI JSON output

PyMuPDF `page.find_tables()` can print a line like:

```text
Consider using the pymupdf_layout package for a greatly improved page layout analysis.
```

That line was leaking to stdout and corrupting JSON reports. The helper now suppresses stdout/stderr around `find_tables()`. `apply-suggestions` also uses lenient JSON loading to tolerate older reports with such preamble noise.

## Key Safety Takeaway

q7 suggestions are useful but must be treated as patch proposals, not trusted edits. The first real test demonstrated why: q7 wanted to delete paragraphs, but the evidence gate blocked deletion. This preserves safety while still allowing lower-risk layout repairs.
