## Implemented

### 1. OOXML-backed indentation and font adapters

`normalize_indentation` and `change_font` no longer rely only on high-level python-docx formatting.

Added low-level OOXML helpers:

```text
set_paragraph_indent_ooxml()
set_run_font_all()
```

`normalize_indentation` now sets both python-docx paragraph format and `w:ind` directly:

```text
w:left = 360 twips
remove w:hanging
remove w:firstLine
```

`change_font` now sets:

```text
w:rFonts w:ascii
w:rFonts w:hAnsi
w:rFonts w:eastAsia
w:rFonts w:cs
```

This matters for Word/LibreOffice because only setting `run.font.name` is often incomplete.

### 2. Native table normalization adapter

Added adapter:

```text
normalize_tables
```

It can be invoked via q7 suggestion canonicalization from:

```text
table_col_width
table_cell_border
table_count_reconcile
table / tbl / cell / border / column patch names
```

It normalizes native DOCX tables by setting:

```text
w:tblW type=pct w=5000
single borders on all edges/inside grid
cell margins top/bottom/start/end
table alignment center
cell paragraph spacing = 0
```

CLI option added:

```bash
--normalize-tables
```

Example:

```bash
uv run .../pdfdocx5.py convert source.pdf -o out.docx \
  --path xa --max-pages 3 --compact-on-overflow --normalize-tables
```

### 3. Text replacement adapter

q7 found a new repair type during in-loop test:

```text
text_replacement: remove spaces before punctuation in p[3]
```

Added adapter:

```text
text_replacement
```

It supports:

- explicit q7 `change 'old' to 'new'` hints
- fallback cleanup for spaces before punctuation, e.g. `page .` → `page.`

Current behavior is targeted only; it requires q7 to identify paragraph indices like `p[3]`.

### 4. Corrected DOCX stats table/paragraph counts

Previous `docx_stats()` used raw byte counts:

```python
xml.count(b"<w:p")
xml.count(b"<w:tbl")
```

This overcounted `w:pPr`, `w:tblPr`, and `w:tblGrid`. Fixed to regex count real elements only:

```python
<w:p(?:\s|>)
<w:tbl(?:\s|>)
```

This changed table QA from misleading `docx_native_tables: 8` to the correct `docx_native_tables: 1` on the large 3-page subset.

## Key Findings

1. Table QA became much more meaningful after fixing `docx_stats()` element counting. The large 3-page subset now correctly reports 1 source table vs 1 DOCX native table.
2. Table normalization does not break renderability and keeps the compact-overflow fix: 5 rendered pages → 3 pages by turn 2.
3. q7 may detect visual punctuation issues that do not exist in editable text. This can happen because rendered glyph spacing and text extraction differ. The text adapter should verify actual DOCX text before changing anything.
4. OOXML-backed font/indent adapters are now ready for more real q7 suggestions.
