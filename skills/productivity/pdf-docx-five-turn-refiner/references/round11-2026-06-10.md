## Actions Taken

### 1. Implemented composite QA failure score

`qa()` now emits:

```json
"failure_score": {
  "score": 35,
  "severity": "minor",
  "reasons": [...]
}
```

It combines:

- page count delta
- table count delta
- table geometry status
- low editable text vs source native text
- full-page raster risk
- render failure
- high visual RMSE

Purpose: prevent low pixel RMSE from hiding poor editability or table/page failures.

### 2. Fixed the compact loop architecture

Problem discovered in real contracts:

```text
Round10 contract_en3 / contract_zh3: 3 source pages -> 6 rendered pages
```

Initial aggressive compact attempt over-collapsed because compact profiles were applied cumulatively:

```text
turn1 level0 -> 6 pages
turn2 level3 -> 6 pages
turn3 level6 stacked on already compacted output -> 1 page
```

Fix:

- compact profiles now evaluate from the original candidate, not recursively stacked output
- refiner tracks `best_turn` / `best_failure_score`
- final output copies the best-scored candidate, not blindly the last turn
- early stop now requires page parity when page count is known

### 3. Added stepwise page-density profiles

The key empirical finding from a partial-empty-paragraph sweep:

```text
contract_en3, compact level4 + remove empty layout paragraphs:
k=0  -> 6 pages
k=4  -> 5 pages
k=6  -> 4 pages
k=10 -> 3 pages
k=12 -> 2 pages

contract_zh3:
k=0  -> 6 pages
k=4  -> 5 pages
k=8  -> 4 pages
k=10 -> 3 pages
k=14 -> 2 pages
```

Therefore aggressive profiles now remove empty layout paragraphs incrementally:

```text
level5 -> remove_empty_paragraph_limit 4
level6 -> remove_empty_paragraph_limit 8
level7 -> remove_empty_paragraph_limit 10
level8 -> remove_empty_paragraph_limit 12
```

This gives the loop a real 6→5→4→3 search path.

### 4. Added autonomous battle runner

New script:

```text
scripts/auto_battle_pdfdocx5.py
```

Run with:

```bash
uv run ~/.hermes/skills/productivity/pdf-docx-five-turn-refiner/scripts/auto_battle_pdfdocx5.py \
  --root ~/Works --probe-limit 300 --run-limit 3 \
  --out /tmp/pdfdocx5-auto-battle
```

It:

1. discovers PDFs under `~/Works`
2. probes risk with PyMuPDF
3. selects high-risk/high-value candidates
4. runs bounded conversion/refinement
5. ranks results by composite failure score
6. writes `auto-battle-report.json`

A bug was found and fixed immediately: it referenced `probe.text_chars`, but the actual field is `probe.total_text_chars`.
