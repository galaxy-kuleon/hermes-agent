## Problem

`pdf2docx` often emits 1-row native DOCX tables for layout/furniture:

- footers / page headers
- section headings
- slide handout grids
- small form labels

Counting all native DOCX tables against PyMuPDF source semantic tables created false table drift.

## Fix Implemented

Added DOCX table classification to `scripts/pdfdocx5.py`:

```python
def classify_docx_table(rows, cols, total_chars, sample_text) -> str:
    ...
    return "layout_or_furniture" | "content_table"

def docx_table_summaries(docx: Path) -> dict:
    ...
```

`qa()["table_qa"]` now includes:

```json
{
  "source_tables_detected": 2,
  "docx_native_tables": 5,
  "docx_content_tables": 2,
  "docx_layout_tables": 3,
  "table_count_delta": 3,
  "content_table_count_delta": 0,
  "layout_table_overuse_when_no_source_tables": 0,
  "table_summaries": [...]
}
```

`failure_score` now penalizes `content_table_count_delta` rather than raw `table_count_delta`, and applies only a small explicit penalty for layout-table overuse when the source has no tables.
