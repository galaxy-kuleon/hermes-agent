## Key Findings

1. The old fixture set was too narrow. Fresh real PDFs immediately exposed larger failures: contract pages overflow 3→6 even after five compact turns.
2. `--compact-on-overflow` is insufficient for real contract layouts with logos/stamps/tables/images. We need a stronger page-density/section constraint adapter.
3. Table count/geometry drift is now the dominant failure across real contracts/legal decisions.
4. Mixed native/raster samples can have deceptively low pixel-diff RMSE while still being semantically poor (`visible_text_chars=90`, `full_page_raster_risk=medium`). QA ranking must combine visual metrics with editability/raster-risk.
5. XB scanned path works as intended for content-correct DOCX: editable text + correct page count, but low layout fidelity.

## Next Repair Targets

1. Page-density adapter for contract overflow:
   - detect pages with massive blank first render page / source content shifted to later pages
   - try aggressive compact profile beyond current level 4
   - reduce image/logo/stamp footprint when they dominate page flow
   - possibly convert some floating images to anchored/header-like layout

2. Table-grid reconciliation adapter:
   - merge/split candidate tables when source table count is lower
   - compare source/rendered row/column estimates
   - preserve actual source-like grid rather than generic table normalization

3. Mixed-page route splitting:
   - for mixed native/raster PDFs, process raster-heavy pages via XB or image-aware content extraction instead of forcing whole document through XA

4. QA ranking update:
   - combine RMSE with visible_text_chars, raster risk, page_count_delta, table_count_delta, and table_geometry_status
   - low RMSE must not hide editable-content failure
