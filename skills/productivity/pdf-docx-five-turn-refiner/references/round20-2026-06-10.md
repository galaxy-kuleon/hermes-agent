The rendered page is not simply missing tables. It has native tables and page parity, but the recovered text appears as a dense plaintext block rather than source-like government-form layout. This explains why:

- `page_count_delta = 0`
- `max_abs_ink_bbox_delta` is small

The changed-pixel penalty is therefore real and should remain.

## Root Cause Experiment: pdf2docx `line_overlap_threshold`

I tested pdf2docx conversion settings directly. The default pdf2docx setting (`line_overlap_threshold=0.9`) drops many lines in these overlap-heavy forms. Raising the threshold recovers much more text without adding plaintext fallback.

Direct QA on HKIPRD0003 raw candidates:

```text
threshold 0.95: score 62 major, visible_text_chars 7062, changed 0.21505
threshold 0.99: score 38 minor, visible_text_chars 10882, changed 0.19729
threshold 1.00+: score 52 major, visible_text_chars 13289+, table drift worsens
```

So `0.99` is a useful overlap-tolerant sweet spot:

- removes the `visual_changed_fraction_extreme` failure
- improves editable text coverage substantially
- keeps page count at 3
- but still has content-table delta +2 and editable coverage medium

## Important Normalizer Finding

The generic Round11 compact/profile normalizer can damage the overlap-tolerant candidate's geometry. With `line_overlap_threshold=0.99`, raw/preserve-layout QA is:

```json
{
  "score": 38,
  "severity": "minor",
  "visible_text_chars": 10882,
  "changed_channel_fraction_gt24": 0.19729,
  "max_abs_ink_bbox_delta": 0.0312,
  "rendered_to_source_height_ratio": 1.0
}
```

But if generic compact profile is applied first, score jumps to critical/major because visual ink height collapses. Therefore overlap-tolerant XA needs a preserve-layout lane rather than the normal generic normalizer.

## Fixes Implemented

### 1. XA pdf2docx line-overlap parameter

`xa_pdf2docx()` now accepts `line_overlap_threshold`, exposed via CLI:

```bash
--xa-line-overlap-threshold 0.99
```

The conversion report records it:

```json
{"line_overlap_threshold": 0.99}
```

### 2. Preserve-candidate-layout refiner lane

`normalize_docx()` / `refine()` now support:

```bash
--preserve-candidate-layout
```

At compact level 0 this skips the generic compact profile and only preserves essential shell/page-size behavior. This prevents the generic normalizer from destroying already useful pdf2docx geometry.

### 3. Auto-battle best-turn reporting bug fixed

`auto_battle_pdfdocx5.py` previously reported `turns[-1].qa` even when `best_turn` pointed to an earlier candidate. It now reports QA from `best_turn` when available, so `final_docx`, `best_failure_score`, and reported `failure_score` are aligned.

### 4. Experimental overlap-tolerant battle lane

`auto_battle_pdfdocx5.py` now has:

```bash
--overlap-tolerant-xa
```

For XA cases this runs:

```bash
--compact-on-overflow --xa-line-overlap-threshold 0.99 --preserve-candidate-layout
```

and intentionally skips plaintext recovery / table normalization so we can compare the root pdf2docx-overlap fix against the fallback-recovery lane.
