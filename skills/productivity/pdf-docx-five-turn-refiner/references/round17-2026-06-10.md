## Diagnosis

For HKIPRD0003 after page-aware recovery, compact progression was:

```text
turn 1: original candidate, score 65, recovery inserted page1 text
turn 2: compact_level 0, pages 5, page_delta +2, next -> 2
turn 3: compact_level 2, pages 4, page_delta +1, next -> 3
turn 4: compact_level 3, pages 4, page_delta +1, next -> 4
turn 5: compact_level 4, pages 4, page_delta +1, no empty paragraph removal reached
```

The useful profiles with empty paragraph removal start at compact level 5:

```python
{"remove_empty_paragraph_limit": 4}
{"remove_empty_paragraph_limit": 8}
...
```

Because recovery consumes a turn, the default stepwise compact strategy was too slow for the five-turn budget.

## Fix Implemented

In `refine()`, when `recovered_once` is true and `page_delta > 0`, jump directly to at least compact level 5:

```python
if recovered_once and page_delta > 0 and compact_level < 5:
    next_level = min(len(COMPACT_PROFILES) - 1, max(5, compact_level + jump))
else:
    next_level = min(len(COMPACT_PROFILES) - 1, compact_level + jump)
```

This preserves the conservative default for normal overflow cases, but lets overlap-recovery cases reach empty-paragraph removal inside five turns.

Also tuned inline recovery text to use smaller micro text/line spacing in `insert_paragraph_before()` so source page-1 recovery is dense enough to fit.
