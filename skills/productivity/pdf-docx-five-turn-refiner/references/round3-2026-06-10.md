# Round 3 Cultivation Log — 2026-06-10

Third cultivation pass after Noel said "continue" and mid-turn asked:

> do you think q7 can see the input pdf png and output docx's page png and docx xml and suggest a fix?

Answer from implementation + test: **yes**. q7 can take source page PNG, rendered DOCX page PNG, and compact DOCX OOXML context, then produce useful `fix_suggestions` with OOXML hints. q7 should suggest only; deterministic code should apply only whitelisted patches.

## Implemented

### 1. Page-count repair / compact profiles

Added opt-in:

```bash
--compact-on-overflow
```

When QA reports `page_count_delta > 0`, refinement continues instead of stopping and increments a compact profile across up to five turns:

```text
level 0: margin 0.75, space_after 3.0pt, line_spacing 1.00, font_delta  0.00
level 1: margin 0.60, space_after 1.5pt, line_spacing 0.95, font_delta -0.25
level 2: margin 0.50, space_after 0.5pt, line_spacing 0.90, font_delta -0.50
level 3: margin 0.40, space_after 0.0pt, line_spacing 0.86, font_delta -0.75
level 4: margin 0.32, space_after 0.0pt, line_spacing 0.82, font_delta -1.00
```

This targets page overflow deterministically, without VLM edits.

### 2. Cheap page-risk evidence and table QA

QA now collects PyMuPDF evidence:

  "source_tables_detected": 1,
  "source_images_detected": 0,

```

and table QA:

  "source_tables_detected": 1,
  "docx_native_tables": 7,
  "table_count_delta": 6,
  "has_native_tables_when_source_tables_detected": true
}
```

Added q7 page policy:

```bash
--judge-pages risk
```

This selects first/last/middle plus highest-risk pages by tables/images/drawings/low text.

### 3. q7 + source PNG + output PNG + DOCX OOXML context

Added:

```bash
--q7-xml-context
```

When enabled, the q7 judge receives:

- source PDF page PNG
- rendered DOCX page PNG
- compact DOCX OOXML excerpts from `word/document.xml` and `word/styles.xml`
  - `sectPr`
  - first `w:tbl`
  - first `w:drawing`
  - paragraph properties + text summaries
  - Normal style

The q7 response schema now asks for:

```json
fix_suggestions: [
  {
    "patch_type": "...",
    "target": "...",
    "rationale": "...",
    "ooxml_hint": "...",
    "risk": "..."
  }
]
```

## New Findings

1. `--compact-on-overflow` worked very well for the 3-page large-PDF subset: 5 rendered pages → 3 rendered pages in 2 turns.
2. q7 with OOXML context produces more actionable suggestions than image-only q7. It named paragraph indices and OOXML-level hints like `w:ind`, `w:rFonts`, and `<w:p>` removal.
3. q7 suggestions can be aggressive (`delete_paragraphs` with high risk). Must pass through whitelist + source-evidence gates before applying.
4. PyMuPDF table evidence is useful but rough; consider `pymupdf_layout` or pdfplumber as a future optional dependency for better table QA.
