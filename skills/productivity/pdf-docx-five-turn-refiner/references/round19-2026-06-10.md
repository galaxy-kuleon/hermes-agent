## Human/Technical Diagnosis

The current recovery path is still too plaintext-like. It restores:

- editable text coverage
- page count parity
- broad ink bbox/height
- native/content table parity

But it does not restore source-like form/table layout. The `changed_channel_fraction_gt24 >= 0.25` signal is a real human-visible defect.

## Important Bug Found

The page-aware recovery helper originally used:

```python
if 'w:br' in xml or 'w:sectPr' in xml:
    return p
```

This incorrectly treated normal line breaks (`<w:br/>`) as page boundaries. Inspection of the DOCX body showed many ordinary line breaks inside tables/paragraphs before the true section break:

```text
body[1] tbl br=1 text='Application for registration...'
body[4] tbl br=2 text='1. a. General notes...'
body[5] p   br=1 text='is for electronic filing only...'
...
body[18] p sect=1 text=''
body[43] p sect=1 text=''
```

Therefore, recovery text could be inserted too high in the page, before a normal line-break paragraph rather than before a real page/section boundary.

## Fix Implemented

`first_breakish_paragraph()` now ignores normal line breaks and only treats page/section boundaries as insertion anchors:

```python
if 'w:sectPr' in xml or 'w:type="page"' in xml or "w:type='page'" in xml or 'lastRenderedPageBreak' in xml:
    return p
return doc.paragraphs[-1] if doc.paragraphs else None
```

This is semantically correct even though it does not by itself solve the high changed-pixel fraction. It prevents future recovery text from being inserted before ordinary inline line breaks.

## Next Direction

The likely right next step is **table-aware inline recovery**:

1. Use PyMuPDF `page.find_tables()` for source page table regions.
2. Extract source tables with `table.extract()` where possible.
3. For overlap-loss forms, insert missing text into/near corresponding native DOCX table regions rather than a global plaintext block.
4. Or reconstruct page-level form regions as native DOCX tables from source table geometry and text, then suppress only the plaintext fallback.
5. Keep q7/human contact sheet review because changed-fraction alone catches true layout mismatch but doesn't say how to fix it.
