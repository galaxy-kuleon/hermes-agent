### 2. Visual diff metrics for regular QA contact sheets

`qa --contact-sheet` now also reports:

```json
"visual_diff_metrics": [
  {
    "page": 1,
    "source_vs_rendered": {
      "mean_abs_rgb_delta": 15.739,
      "rmse_rgb_delta": 41.822,
      "changed_channel_fraction_gt24": 0.16085
    }
  }
]
```

These are simple pixel metrics, not a final quality score. Use them as a trend/risk signal only.

### 3. Table geometry QA

QA now adds `table_geometry_qa` when source table evidence exists and DOCX renders to PDF.

It compares PyMuPDF-detected source PDF tables with tables detected in the rendered DOCX PDF:

```json
{
  "source_tables": 1,
  "rendered_tables": 1,
  "table_count_delta": 0,
  "source_geometry": [...],
  "rendered_geometry": [...],
  "paired_geometry": [
    {
      "source_rows_cols": [4, 4],
      "rendered_rows_cols": [4, 4],
      "bbox_norm_delta_rendered_minus_source": [...]
    }
  ]
}
```

This is heuristic but much more useful than table count alone.

## Findings

1. The three-column artifact is very useful for a human reviewer: source PDF, before DOCX, after DOCX are immediately comparable.
2. On the large 3-page table sample, simple visual metrics improved from source_vs_before RMSE 43.906 to source_vs_after RMSE 41.822. Treat this as weak trend evidence, not a final visual quality score.
3. Table geometry currently detects 1 table before and after, matching the source count. Future work should compare bbox/column deltas more strictly.
4. Mocked q7 suggestion coverage now exercises `apply-suggestions` without depending on live q7.
